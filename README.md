# skill-commander-intent

命令意图识别技能（Command Intent Recognition Skill）：将用户的自然语言输入解析为结构化的命令意图，包括意图分类、参数提取和执行路径确定。

## 项目解决什么问题

在 AI 助手（如 Aily）处理用户请求时，最大的瓶颈之一是**准确理解"用户到底想让我做什么"**。用户往往以口语化、省略式甚至隐晦的方式表达需求，例如：

- "帮我处理一下这个" —— 操作对象和操作类型都不明确
- "明天的会还开吗" —— 是查询日程，还是取消会议？
- "看看这个怎么样" —— 是分析、审核还是预览？

本技能通过一套**意图识别工作流**，把模糊的自然语言转化为结构化、可路由的命令（意图类别 + 参数 + 置信度 + 执行路径），让助手能够：

- 区分操作请求与纯信息请求，避免对闲聊式提问误触发工具
- 把同一句话归入明确的意图类别，并提取出执行所需的参数
- 对歧义和缺失参数主动澄清，而不是猜测执行
- 将解析结果路由到正确的工具或工作流

简言之：**它解决的是"助手如何听懂并正确执行用户指令"的问题，是自然语言与系统工具之间的翻译层。**

## 主要功能

### 1. 意图检测
判断用户输入是否包含命令意图：

| 类型 | 说明 | 示例 |
|------|------|------|
| 显性命令 | 动词 + 对象，直接表达操作 | "帮我生成报告"、"搜索最近文档" |
| 隐性命令 | 以问题形式表达操作需求 | "今天的日程是什么？" → 查询日程 |
| 纯信息请求 | 不涉及操作，仅寻求信息 | "什么是飞书多维表格？" → 不触发本技能 |

### 2. 意图分类
将检测到的意图归入以下核心类别之一：

| 类别 | 说明 | 典型动词 |
|------|------|---------|
| `create` | 创建新资源 | 创建、生成、新建、添加、制作 |
| `read` | 查询/读取信息 | 查看、搜索、查找、获取、列出、显示 |
| `update` | 修改现有资源 | 修改、更新、编辑、调整、更改 |
| `delete` | 删除资源 | 删除、移除、清空、取消 |
| `execute` | 执行特定操作 | 执行、运行、发送、导出、同步、通知 |
| `analyze` | 分析/处理数据 | 分析、统计、汇总、计算、对比 |
| `coordinate` | 协调/安排事项 | 安排、预约、协调、邀请、提醒 |

涉及多个类别时，按主要操作确定主类别，次要操作为子意图。

### 3. 参数提取
从用户输入中提取结构化参数：

- **核心参数类型**：`target`（操作对象）、`scope`（作用范围）、`criteria`（筛选条件）、`content`（内容描述）、`recipient`（接收方）、`deadline`（时间约束）
- **提取规则**：显式参数（用户直接陈述）、隐式参数（从上下文推断）、缺失参数（执行必需但未提供 → 标记为待确认）

### 4. 置信度评估
| 置信度 | 判定 | 动作 |
|--------|------|------|
| 高 | 意图明确、参数完整 | 直接执行 |
| 中 | 较明确，但有歧义或缺失参数 | 执行前简要确认 |
| 低 | 意图模糊或无法匹配类别 | 请求用户澄清 |

### 5. 执行路由
根据分类结果将请求路由到对应工具或工作流（如 `create` → 创建工具、`read` → 查询工具、`analyze` → 数据分析工具等）。

### 6. 歧义处理
当输入存在多种合理解读时：列出候选意图 → 请求用户澄清 → 若无明显更优解读，按高置信度意图执行并说明假设。

### 7. 领域模式参考
内置 `references/command_patterns.md`，覆盖飞书文档操作、日程与会议、多维表格、即时消息、任务管理、通用分析请求六大领域的典型命令结构和参数组合。

## 安装方法

本技能为 AI 助手技能包（Skill），标准目录结构如下：

```
skill-commander-intent/
├── SKILL.md                        # 技能主文件（含 frontmatter 元信息）
└── references/
    └── command_patterns.md         # 常见命令模式参考
```

### 方式一：Aily 导入（推荐）
在 Aily 中直接导入本技能包（zip 压缩包或 `skill-commander-intent/` 目录），系统根据 `SKILL.md` 中的 `name`、`label`、`description` 自动注册技能。

### 方式二：通用 Skill 目录
将 `skill-commander-intent/` 目录放入助手的技能根目录（如 `.skills/` 或 `.user_skills/`），重启会话后技能即可被发现和调用。

### 要求
- 技能依赖 AI 助手具备工具/工作流路由能力（如飞书文档、日程、表格、消息、任务等工具）
- 无需安装第三方依赖，纯 Markdown 技能定义

## 使用方法

启用本技能后，直接以自然语言向助手下达操作指令，助手将自动执行意图识别工作流：

1. **触发条件**：消息中包含显性或隐性的命令、操作请求、或需要结构化解析的操作意图；纯信息请求不触发
2. **处理流程**：意图检测 → 意图分类 → 参数提取 → 置信度评估 → 执行路由
3. **领域场景**：涉及飞书文档、日程管理、多维表格、任务管理等特定领域时，助手会结合 `references/command_patterns.md` 中的领域模式进行识别
4. **交互确认**：当意图置信度为中/低或参数缺失时，助手会先与你确认或请求澄清，而不是直接猜测执行

## 输入输出示例

### 示例 1：显式命令（高置信度）

**输入：**
> 帮我创建一个关于项目周报的云文档

**解析过程：** 意图 `create`，类型=文档，标题=项目周报，主题=项目进展

**输出：**
```
意图：create
目标：云文档
参数：
  - type: 文档（显式）
  - title: 项目周报（显式）
  - topic: 项目进展（显式）
  - template: 缺失
置信度：高
执行路径：文档/表格创建工具
```

### 示例 2：隐性命令

**输入：**
> 这周有哪些会议

**解析过程：** 问题形式表达查询需求 → 意图 `read`

**输出：**
```
意图：read
目标：会议
参数：
  - time_range: 本周（隐式）
  - attendee: 缺失
  - status: 缺失
置信度：高
执行路径：搜索/查询工具
```

### 示例 3：歧义输入（低置信度，请求澄清）

**输入：**
> 帮我处理一下这个

**解析过程：** 目标"这个"不明确，缺少操作类型 → 置信度低

**响应：**
> 您希望我对当前内容进行什么操作？可以创建新文档、生成摘要、或修改格式。

### 示例 4：多参数提取

**输入：**
> 在任务表添加一条记录，负责人是王五，状态是进行中

**输出：**
```
意图：create
目标：任务表记录
参数：
  - table: 任务表（显式）
  - fields: {负责人: 王五, 状态: 进行中}（显式）
置信度：高
执行路径：多维表格数据操作工具
```
